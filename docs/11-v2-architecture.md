| 事業 | AIが自動でやること | 承認 | 公開 | 本人の作業 |

画像販売と、即時提携できるA8案件。各事業の1日上限は最初は1で、承認率・反応を見て上げる。

## 1. 何がどこで動くか [確定]

```
 スマホ（PWA / GitHub Pages）           GitHub Actions（3時間ごと・無料）
  ログイン・確認・承認・提出・停止          python -m aiworker.cloud run
        │ 公開キー + 本人ログイン                │ 秘密キー（Secretsのみ）
        ▼                                        ▼
 ┌──────────────── Supabase（無料）────────────────┐
 │ Postgres: 安全ルールはここで強制（RLS・関数・トリガ）│
 │ Auth: 本人1名のみ（新規登録は無効）               │
 │ Storage: プレビュー / 提出用原寸（非公開・署名URL）│
 └───────────────────────────────────────────────────┘
        ▲                                        │
        │ 本人操作（週1回・約5分）                  ├─ Gemini API（文章・無料枠）
  Adobe Stock Contributor                         └─ Cloudflare Workers AI（画像・無料枠）
  ZIP（画像+CSV）をアップロード→提出
```

- **PCは不要。** ⑤は生成から提出用ファイル作成まで全てクラウドで完結する。Macワーカーは
  動画・BGMなど重い処理を行う事業（①②）で使う予定で、⑤では使わない。
- **安全ルールはデータベースが強制する。** アプリ・パイプライン・将来のMacのどれから
  操作しても同じ規則に縛られる（アプリ側のバグで規則が抜けない）。

| 規則 | 強制する場所 |
|---|---|
| 「承認済み」にできるのは `approve_item()` だけ（サービスキーでも直接は不可） | DBトリガ |
| 承認後に内容が変わると承認は無効化 → 確認待ちへ戻る | DBトリガ |
| 状態遷移は表に載っている組み合わせのみ（公開済みは終端） | DBトリガ |
| 自動承認は「アカウントが自動設定」「ブロックなし」「サンプルでない」の全てを満たす時だけ | `approve_item()` |
| 古い画面からの承認（表示後に内容が変わった）は拒否、二重タップは無害 | `approve_item()` |
| 却下・修正依頼・保留は人間のみ。修正依頼は内容の記入必須 | `decide_item()` |
| ブロック解除は理由の記入必須、警告として記録 | `approve_item()` |
| ブラウザは items / approvals / controls / jobs / events に**書き込み権限なし** | GRANT |
| 未ログインの訪問者は何も読めない。ログインしても `owners` 未登録なら何も見えない | GRANT + RLS |
| 全体停止中は自動承認・生成をしない | `approve_item()` + パイプライン |

## 2. ⑤ の流れ [確定]

1. テーマ×切り口×語り口を、最近使ったものを避けて選ぶ（同じ構図の量産を防ぐ）
2. Gemini が英語の生成プロンプト・タイトル（70字以内）・キーワード（最大49）・カテゴリを作る
3. 規約スクリーニング（作家名・有名IP・実在人物・ロゴ等）→ 該当すれば**画像を作らず**ブロック
4. Cloudflare（FLUX.1 schnell）で 1024px 生成 → Adobe 最低 4MP へ拡大（上限2.5倍）
5. 自動検査：単色・極端な縦横比・**過去画像とのほぼ重複**（dHash）→ 該当すればブロック
6. プレビュー（スマホ用）と原寸（提出用）を非公開ストレージへ
7. 自動承認（既定）→「提出待ち」へ。注意付き・修正依頼・サンプルは必ず「確認待ち」
8. **本人**：アプリの「提出」でZIP（画像＋Adobe用CSV）を落とし、Adobeへアップロード・提出
9. アプリで「提出した」→ 提出済み（根拠を記録）。原寸は自動削除（容量節約）

量の上限（3重）：アカウントの1日上限（既定1・アプリで0〜50に変更可）／1日の生成上限10
（無料枠の保護）／未処理30件で生成停止（さばけない量を作らない）。

## 3. 本人操作が残る部分 [確定]

| 操作 | 頻度 | 理由 |
|---|---|---|
| Adobe Stock への画像アップロードと提出 | 週1回・約5分 | 提出時にCAPTCHAがあり、大量の自動提出はアカウント停止の対象になり得るため自動化しない。タイトル・キーワードはCSVで一括入力されるので手入力はない |
| 提出前の目視（手指・文字化け・ロゴ等） | 提出時 | 機械判定できない。アプリに確認項目を表示 |
| 売上の記録 | 月1回 | Adobe Stock・A8・note・YouTube の売上を取得する公開APIを使っていない。アプリの「事業」から入力 |
| noteへの投稿 | 1本ごと・約1分 | noteに投稿APIがない。非公式な自動化はアカウント停止の危険 |
| YouTubeへの投稿 | 1本ごと・約2分 | 審査を通っていないAPIプロジェクトからの投稿は強制的に非公開になる（審査は数週間） |
| A8の提携申請 | 案件ごと | 広告主の審査がある。本人の判断で申請する |
| 初期設定（アカウント作成・キー発行） | 初回のみ | 本人確認・パスワード・税務情報は本人操作が必要 → `12-setup-claude-in-chrome.md` |

## 6. 運用・停止・復旧・バックアップ

- **止める**：アプリ右上「停止」→ 理由を書いて「すべて止める」。生成も自動承認も止まる。
  アカウント単位なら「事業」→ 状態「一時停止」。完全に止めるなら GitHub の変数
  `AIWORKER_PIPELINE` を `off` に。
- **再開**：赤い帯の「再開」。
- **失敗したとき**：キー切れ・設定ミスは実行が赤（失敗）になり GitHub からメールが届く。
  画像サービスの混雑は自動で次回再試行（3回で諦めて「失敗」表示、その日の枠は空く）。
- **復旧**：スキーマは `supabase/migrations/` を順に適用すれば再現できる。
- **バックアップ** [未実装]：Supabase 無料プランは自動バックアップの保持がない。
  案：週1回 Actions で設定・履歴を JSON に書き出し、本人の Google ドライブへ（公開リポジトリには置けない）。
