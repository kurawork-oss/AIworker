**フェーズ1〜3が安定してから着手します。** 順序を逆にすると、
品質が不安定なものを自動で撒くことになります。

- [ ] 対象プラットフォームの開発者規約を確認し、自動投稿の可否を判断

- [ ] `dry_run: false` + `daily_limit` を半分にして1週間観察
- [ ] 問題なければ通常値に戻す

### アダプタ実装のひな形

```python
# src/aiworker/publishers/x_api.py
from ..core.errors import PublishError, TransientError
from .base import PublishResult

class XPublisher:
    name = "x_api"
    performs_network_io = True          # dry_run 時に自動で無効化される

    def __init__(self, settings):
        self.token = os.environ["X_ACCESS_TOKEN"]   # 必ず環境変数から

    def publish(self, item) -> PublishResult:
        # 429 / 5xx / ネットワーク → TransientError（リトライされる）
        # 400 / 403 / 内容拒否     → PublishError（リトライしない）
        ...
        return PublishResult(True, external_id=..., external_url=...)
```

```python
# publishers/registry.py
from .x_api import XPublisher
ADAPTERS = {"x_api": lambda s: XPublisher(s)}
```

`ADAPTERS` に書かない限り、ファイルが存在してもアダプタは到達できません。
「置いたら有効になる」を避けるための設計です。

## 今後の改善候補（優先度順）

### 高

1. **メトリクス自動取得** — 現在は `metrics add` で手入力。
   X API v2 / YouTube Analytics API は正規の読み取りAPIがあるので、
   書き込みより先にこちらを自動化するのが安全です。
   リーチ急減検知の精度が上がります。
2. **承認UIのモバイル最適化** — 現状でも動きますが、スワイプでの承認/却下があると
   毎日の3分が1分になります。
3. **生成物の履歴比較** — 「先月と比べて切り口が偏っていないか」を可視化。

### 中

3.5. **メトリクス取込（CSV）** — リーチ急減検知の入力が `metrics add` の手入力のままです。
   X Analytics / YouTube Studio のCSVエクスポートを、収益CSVと同じ形で取り込めるように
   するのが次の一手です。手入力は「誰もやらない類の作業」なので、実質いちばん弱い
   ガードレールになっています。

4. **週次の自動サマリーメール** — 現在はDiscord/Slack。メールの方が読む人もいます。
5. **A/Bテスト支援** — 同一テーマで切り口違いを2本出し、リーチを比較して記録する。
6. **複数アカウント運用** — スキーマは `account` カラムで対応済み。CLIの引数対応が必要。

### 低

7. **Postgres対応** — SQLiteで困る規模になったら。`core/db.py` の書き換えだけで済みます。
8. **n8n以外のワークフローエンジン対応** — CLIを叩くだけなので、実質どれでも動きます。

## 意図的に実装しないもの

| 項目 | 理由 |
|------|------|
| 管理画面のスクレイピングによる収益取得 | ダッシュボードのためにアカウントを危険に晒す取引。CSVで2分 |
| 非公式APIによる自動投稿 | 規約違反。本システムが避けるべきリスクそのもの |
| 完全無人モード | `require_human_approval` は設定で無効化できません |
| 複数アカウントへの同一コンテンツ投稿 | プラットフォーム横断のスパム判定で最も検知されやすい |
| 検知回避（プロキシローテーション等） | 規約違反を前提とした機能。実装しません |
